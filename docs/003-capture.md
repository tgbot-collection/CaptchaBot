# Story 003：规则命中消息采集与异步补充信息

## 依赖
Story 001–002。

## 开发任务
- 定位真实规则命中/删除路径；**删除前**提取必要快照：原始文本或 caption、entities、发送者、群组、via_bot、命中规则。采集范围包含现有的消息信号、关键词、Sticker、Bio、姓名、emoji 和 ID 规则，不包含验证码业务消息。
- 保持原有删除行为和延迟：不得在删除前等待 D1、Bio 或推理。
- 命中后将后续处理加入有容量和并发上限的后台队列；删除 API 失败时仍尝试非阻塞入队，但保留原删除异常的传播行为。
- 若 Pyrogram 账号权限允许，单独获取 Bio；设置短超时、短期缓存；处理权限不足、限流和字段缺失，不得虚构 Bio。
- 在 D1 写入 `pending`、`label=NULL`；Bio 或模型不可用时仍可采集。
- 处理重试和重复投递；日志脱敏；限制队列积压和内存。

## 验收标准
- 功能开启或关闭都不影响关键词删除。
- 重试下同一消息最多保留一条 pending 记录。
- 本 Story 不发送管理员通知，也不要求模型存在。
- 填写 `docs/notes/003-notes.md` 并更新进度。

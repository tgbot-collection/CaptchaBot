# Story 002：Cloudflare D1 表结构与 REST 客户端

## 依赖
Story 001。

## 开发任务
- 提供 `samples` 表的 SQL Migration：索引、`label/status` 约束、幂等去重键；唯一键中不直接暴露用户信息。
- 实现异步或线程卸载的 D1 REST HTTP 客户端：最小权限 Token、超时、瞬时错误有限重试、参数化 SQL，正确解析 Cloudflare HTTP 200 但业务失败的响应。
- 提供接口：`create_pending(sample) -> id`、`review(id, label, admin_id) -> changed/already_reviewed`、`get(id)`、`stats()`、`export_reviewed()`；导出需分页和稳定排序。
- 审核更新必须原子执行 `WHERE status='pending'` 并检查影响行数；同一消息重复投递不能重复创建记录。
- 配置全部来自环境变量；写清迁移操作；**不需要 Cloudflare Worker**。
- Mock HTTP 测试覆盖成功、D1 逻辑错误、超时、重复写入、并发和限流。

## 验收标准
- 无真实 Cloudflare 凭证也能执行 Migration 校验和 Mock 测试。
- 重复 callback 不能覆盖已有审核标签。
- D1 故障不会影响现有删除逻辑。
- 本 Story 暂不接入在线 Bot 和管理员 UI。
- 填写 `docs/notes/002-notes.md` 并更新进度。

# Telegram Spam Detector：项目总览

## 目标
在不改变现有关键词秒删能力的前提下，逐步收集人工标注数据，训练可在 ARM64/AMD64 CPU 上运行的轻量 Spam 检测模型。V1 模型只提供预测建议；仅在手动重新训练和部署后更新。

## 当前数据
- `spam.txt`：不到 100 条已确认 Spam 纯文本，无 Telegram 结构化字段，也没有 Ham。
- 在线消息：Pyrogram `Message` 可用于提取快照；Bio 需视权限单独查询。
- 现有关键词规则是唯一自动执行删除的依据。

## 完整流程
1. 收到消息，先提取必要字段快照，保留原始 Unicode。
2. 现有关键词规则照常判断和删除；不等待模型、D1 或 Bio。
3. 对关键词命中的消息启动有并发上限的后台任务：可选查询 Bio、运行本地推理、写入 D1，状态 `pending`，`label=NULL`。
4. **D1 写入成功后**私聊管理员，展示消息、可用的账号信息、命中规则和预测；提供 `✅ Spam` / `❌ Not Spam` 两个按钮。
5. 回调验证管理员身份，原子更新 `pending -> reviewed` 并写入 `spam` 或 `ham`；成功后修改通知。忽略则一直 pending。
6. 人工触发训练：从 D1 导出 reviewed 样本，合并初始 Spam，评估并生成带版本号的模型文件。
7. 手动构建、部署镜像。V1 模型始终只提供建议。

## 开发顺序：每个 Story 一个 Codex 会话
1. `001-init.md`：基础架构、配置、统一样本结构。
2. `002-d1.md`：D1 Schema 和 REST 客户端。
3. `003-capture.md`：关键词命中采集和异步补充信息。
4. `004-review.md`：管理员 Telegram 审核。
5. `005-seed-model.md`：纯正例初始相似度模型。
6. `006-inference.md`：模型预测接入审核通知。
7. `007-retrain.md`：D1 导出、重新训练、可选二分类模型。
8. `008-deploy.md`：多架构 Docker 部署和端到端验收。

## V1 明确不做
AI 自动删除/封禁、头像识别、对所有未命中关键词消息的 Shadow Mode、在线自动学习、定时重训、Cloudflare Worker 网关、外部 LLM API。

## 使用方式
将本包放到现有仓库根目录；每行一条已确认 Spam 写入 `spam.txt`。先让 Codex 只实现 Story 001，再依次进行。真实项目与接口草案有冲突时，以实际代码为依据，先沟通再修订文档。
